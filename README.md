# L2X Panel

**Веб-панель для Xray-core с выходом в интернет через несколько L2TP/IPsec-туннелей**

Клиенты подключаются к серверу по VLESS / VMess / Trojan / Shadowsocks / Hysteria2,<br>
а трафик уходит в интернет через выбранный L2TP-туннель, WireGuard, WARP или напрямую.

## Зачем это

Обычные панели выпускают трафик клиентов с IP самого сервера. L2X Panel решает другую задачу: **один сервер — много выходных IP**. Панель поднимает несколько L2TP/IPsec-подключений к внешним VPN-провайдерам, и каждый клиент или каждая страна получает свой выход в интернет. Если туннель падает, балансировщики переводят трафик на живые.

```
 Клиент (Happ, v2RayTun, Hiddify, Clash, sing-box)
        │  VLESS Reality / VMess / Trojan / SS / Hysteria2 / WireGuard
        ▼
 ┌────────────── Сервер с L2X Panel ──────────────┐
 │  Xray-core: inbounds → routing → outbounds     │
 │      ├── l2tp_germany ─► ppp l2x-germany ──────┼──► 🇩🇪 VPN-провайдер
 │      ├── l2tp_usa     ─► ppp l2x-usa ──────────┼──► 🇺🇸 VPN-провайдер
 │      ├── lb_least_ping (балансировщик) ────────┼──► лучший из туннелей
 │      ├── warp / wireguard / vless …  ──────────┼──► внешние прокси
 │      └── direct ───────────────────────────────┼──► IP сервера
 └────────────────────────────────────────────────┘
```

## Возможности

### Xray и протоколы
- **Inbounds**: VLESS (Reality, Vision), VMess, Trojan, Shadowsocks (включая 2022), **Hysteria2**, WireGuard, SOCKS, HTTP, dokodemo-door.
- **Транспорты**: RAW, WebSocket, gRPC, HTTPUpgrade, XHTTP, mKCP; TLS и Reality с генерацией ключей.
- Управление версией Xray-core (установка любого релиза из GitHub), обновление geoip/geosite, редактор DNS, policy, логов.
- Автопроверка новых релизов Xray-core (по умолчанию раз в 12 ч): баннер в панели и уведомление в Telegram. Обновление ставится только после подтверждения; если текущий конфиг не проходит `xray -test` или ядро не стартует, возвращается прежняя версия.

### Мульти-L2TP
- Неограниченное число L2TP/IPsec-туннелей (strongSwan + xl2tpd), у каждого свой PPP-интерфейс и таблица маршрутизации.
- Watchdog: проверка живости туннелей; упавший туннель отключается и выводится из маршрутизации, балансировщики переключаются на живые, приходит уведомление в Telegram.
- Флаги стран, привязка туннеля к клиенту, inbound или правилу маршрутизации.

### Outbounds
- Форма и JSON-редактор для VLESS, VMess, Trojan, Shadowsocks, SOCKS, HTTP, WireGuard, freedom, blackhole, DNS.
- Импорт по ссылке (`vless://`, `vmess://`, `trojan://`, `ss://`, `socks://`, `http://`, `wireguard://`).
- **Cloudflare WARP** в один клик, **NordVPN** (NordLynx) с выбором страны.
- Генерация ключей WireGuard и вычисление публичного ключа.
- Балансировщики `leastPing` / `leastLoad` с health-check и fallback.
- Статистика по каждому outbound: трафик, текущая, средняя и пиковая скорость, графики за час и сутки.

### Клиенты
- Лимиты трафика, срок действия, старт с первого подключения, автосброс (день / неделя / месяц).
- Лимиты по IP с автобаном лишних адресов, лимиты трафика на отдельные outbounds.
- **HWID-лимиты устройств**, режим «обязательный HWID».
- Массовые операции (выделить все / снять выделение), QR-коды, конфиги WireGuard, страница клиента.

### Подписки
- Форматы: base64, plain, Xray JSON (с Fragment / Noise / Mux), Clash Meta, sing-box, HTML-страница.
- Отдельный HTTPS-сервер подписок; **сертификаты Let's Encrypt на домен или на IP**, без покупки домена.
- Заголовки Happ: `profile-title`, `subscription-userinfo`, `announce`, `providerid`, `subscription-always-hwid-enable`, `new-url` (автоматический перенос клиентов на новый адрес).

### Администрирование
- Дашборд: CPU, RAM, диск, сеть, онлайн, утилизация каждого outbound.
- 2FA (TOTP), секретный путь панели, защита от перебора пароля.
- Telegram-бот: отчёты, онлайн, трафик, бэкапы, перезапуск Xray, уведомления.
- **REST API** с токенами и **вебхуки**.
- **Мульти-ноды**: синхронизация клиентов и конфигурации на другие серверы.
- Бэкап и восстановление (файл и Telegram), BBR, speedtest, просмотр логов.
- Русский и английский интерфейс, тёмная и светлая темы.

## Установка

### Требования
- VPS с **Debian 12+** или **Ubuntu 22.04+**, x86_64 или arm64, root-доступ.
- 1 vCPU / 512 МБ RAM достаточно для десятков клиентов.
- Для L2TP: ядро с модулями `ppp_generic`, `l2tp_ppp` и xfrm (на KVM работает; на OpenVZ/LXC обычно нет).

### Установка одной командой

```bash
bash <(curl -Ls https://raw.githubusercontent.com/eliot-voodi/l2x-panel/main/install.sh)
```

Установщик задаст несколько вопросов в интерактивном меню. На каждый вопрос можно просто нажать Enter: подставится значение по умолчанию. **Пароль администратора и секретный путь генерируются случайно** и в конце установки один раз печатаются в консоль.

```
? IP или домен сервера (для ссылок и подписок) [203.0.113.10]:
? Логин администратора [admin]:
? Пароль администратора [<случайный>]:
? Секретный путь панели (- = без пути) [<случайный>]:
? Как открывать панель?
    1) Через nginx на порту 80 (рекомендуется)
    2) Напрямую на отдельном порту, без nginx
  Выбор [1]:
? Версия Xray-core (latest или тег, например v26.10.31) [latest]:
? HTTPS для подписок (нужен для Happ и др.) — сертификат Let's Encrypt:
    1) На IP сервера (без домена, 6 дней, продлевается автоматически)
    2) На домен (90 дней, A-запись домена должна указывать на сервер)
    3) Пропустить (можно позже: Настройки → Сертификаты)
  Выбор [3]:
```

После подтверждения он поставит Xray-core, strongSwan, xl2tpd, nginx и Python-окружение, создаст systemd-сервисы, при выборе HTTPS выпустит сертификат и включит HTTPS-сервер подписок, а в конце покажет данные для входа:

```
  ════════════════════ L2X Panel установлена ════════════════════

  Панель:   http://203.0.113.10/<путь>/
  HTTPS:    https://203.0.113.10:2053/<путь>/
  Логин:    admin
  Пароль:   <сгенерированный пароль>

  Меню управления на сервере: l2x
  Сохраните пароль — он больше не будет показан (сброс: l2x reset-password).
```

Если на сервере включён `ufw`, установщик предложит открыть нужные порты.

### Обновление и удаление

Повторный запуск той же команды на сервере с установленной панелью откроет меню:

```
➜ L2X Panel уже установлена
? Что сделать?
    1) Обновить панель (данные и настройки сохраняются)
    2) Удалить панель
    0) Выход
```

То же доступно из CLI: `l2x update` и `l2x uninstall`. При удалении данные в `/var/lib/l2xpanel` и `/etc/l2xpanel` сохраняются, и повторная установка подхватит их.

### Автоматическая установка

Для скриптов и Ansible: флаг `--yes` отключает вопросы, ответы берутся из переменных окружения.

```bash
curl -Ls https://raw.githubusercontent.com/eliot-voodi/l2x-panel/main/install.sh | \
  L2X_PATH=mypanel L2X_SSL=ip bash -s -- --yes
```

Пароль и (если не задан `L2X_PATH`) секретный путь будут сгенерированы и выведены в конце установки. Не коммитьте и не публикуйте реальные пароли.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `L2X_HOST` | внешний IPv4 | IP или домен для ссылок и подписок |
| `L2X_ADMIN` | `admin` | Логин администратора |
| `L2X_PASSWORD` | случайный | Необязательно: свой пароль (≥ 8 символов). Иначе генерируется |
| `L2X_PATH` | случайный | Секретный путь панели, `-` — без пути |
| `L2X_MODE` | `nginx` | `nginx` — панель на :80 за nginx; `direct` — панель сама слушает `L2X_PORT` |
| `L2X_PORT` | `2053` | Порт панели для `L2X_MODE=direct` |
| `L2X_SSL` | `none` | `ip` или `domain` — выпустить сертификат Let's Encrypt и включить HTTPS-подписки |
| `L2X_DOMAIN` | — | Домен для `L2X_SSL=domain` |
| `L2X_EMAIL` | — | E-mail для Let's Encrypt |
| `XRAY_VERSION` | последний релиз | Версия Xray-core, например `v26.10.31` |
| `L2X_REPO`, `L2X_BRANCH` | этот репозиторий, `main` | Откуда брать код |

Флаги: `--yes` — без вопросов, `--update` — обновить, `--uninstall` — удалить.

### Установка из клона

```bash
git clone https://github.com/eliot-voodi/l2x-panel.git
cd l2x-panel
sudo bash install.sh
```

### Docker

```bash
git clone https://github.com/eliot-voodi/l2x-panel.git && cd l2x-panel
# при необходимости задайте L2XPANEL_PUBLIC_HOST в docker-compose.yml
docker compose up -d --build
docker compose logs -f   # пароль администратора печатается при первом старте
```

Панель будет доступна на `http://<IP>:2053/`. Пароль генерируется при первом запуске и пишется в лог и в `./data/initial_credentials.txt`. Контейнеру нужны `network_mode: host` и `privileged: true` (PPP-устройства, IPsec, порты Xray). Для продакшена рекомендуется установка на хост: так проще работают автопродление сертификатов и L2TP.

## Первые шаги

1. **Inbounds → Добавить**: VLESS Reality создаётся в пару кликов, ключи генерируются автоматически. Клиенты подключаются на `:443` через nginx (см. «Публичный вход :443»).
2. **L2TP → Добавить**: сервер, логин, пароль и PSK вашего VPN-провайдера, затем Connect. Появится outbound `l2tp_<name>`.
3. **Клиенты → Добавить**: выберите outbound (туннель, балансировщик или `direct`), лимиты и срок.
4. Отдайте клиенту ссылку подписки или QR-код со страницы клиента.

## Подписки и HTTPS

Многие клиенты (например, Happ) принимают подписку только по HTTPS. Домен для этого не обязателен:

1. **Settings → Certificates**: нажмите «IP сервера» → «Выпустить». Let's Encrypt выдаст сертификат на IP (профиль `shortlived`, 6 дней, acme.sh продлевает его автоматически каждые ~3 дня). С доменом получится обычный сертификат на 90 дней.
2. **Settings → Subscriptions**: включите «Отдельный сервер подписок» (порт `2096`), выберите сертификат и укажите тот же IP или домен в поле «Домен в ссылках».
3. Ссылки клиентов: `https://ваш-домен/sub/<token>` (только порт 443).

Для Let's Encrypt порт **80** должен быть открыт снаружи (ACME). nginx отдаёт проверки из `/var/www/l2x-acme`.

## Публичный вход :443 (один домен)

В **Настройки → Панель** задаётся **публичный домен** (меняется в любой момент). Клиентам нужен только он и порт **443**:

- Панель: `https://домен/`
- Подписки: `https://домен/sub/<token>` (порт 2096 больше не используется)
- Коннекты: адрес в ссылках — домен, порт `443`

Xray — только `127.0.0.1`. nginx `:443` (`/etc/nginx/l2x/`): Reality/TLS по SNI → Xray; WS/gRPC/… — TLS на домене → путь в Xray; `:80` — ACME и редирект на HTTPS.

Ограничения (захардкожены): порты **22/80/443** нельзя выбрать для inbound; снаружи inbound-порты и legacy 2096/2053 режет `L2X_PORTBAN`; `nginx -t` и `xray -test` обязательны до apply.

### HWID и Happ

- **Лимит устройств** у клиента ограничивает число устройств, которые могут получать подписку.
- **«Обязательный HWID»** в настройках подписок не выдаёт подписку приложениям, которые не передают `X-HWID`.
- **«Переносить клиентов на текущий адрес»**: если вы сменили домен или порт, приложение при следующем обновлении получит заголовок `new-url` и само перейдёт на новый адрес.
- Happ выполняет команды `subscription-always-hwid-enable` и `new-url` только при заданном **Provider ID** (бесплатно на [happ-proxy.com](https://happ-proxy.com)).

## CLI `l2x`

На сервере доступно меню `l2x` (или команды напрямую):

| Команда | Действие |
|---|---|
| `l2x` | Интерактивное меню |
| `l2x status` | Состояние сервисов, версия Xray, адрес панели |
| `l2x url` | Адрес панели |
| `l2x restart` | Перезапустить панель и Xray |
| `l2x reset-password` | Сбросить логин и пароль администратора |
| `l2x disable-2fa` | Отключить 2FA |
| `l2x reset-path` | Сбросить секретный путь панели |
| `l2x backup` | Бэкап в `/root` |
| `l2x update` | Обновить панель до последней версии с GitHub |
| `l2x uninstall` | Удалить панель (данные сохраняются) |

В меню также есть выпуск SSL, BBR, открытие портов, speedtest, обновление geo-файлов и логи.

## Как это работает

| Компонент | Где | Роль |
|---|---|---|
| L2X Panel (FastAPI + uvicorn) | `/opt/l2xpanel`, `127.0.0.1:8090` | Веб-интерфейс, API, подписки, генерация конфига Xray, watchdog |
| nginx | `:80`, `:443` | Reverse proxy к панели, webroot Let's Encrypt, публичный вход для inbounds (stream SNI + HTTPS path) |
| Xray-core | `/usr/local/bin/xray` | Inbounds, маршрутизация, outbounds, статистика (gRPC API `127.0.0.1:10085`) |
| strongSwan + xl2tpd | systemd | IPsec и L2TP; у каждого туннеля свой PPP-интерфейс `l2x-<name>` |
| acme.sh | `/root/.acme.sh` | Выпуск и продление сертификатов Let's Encrypt |

Outbound `l2tp_<name>` в Xray привязан к интерфейсу туннеля через `sockopt.interface`, поэтому трафик клиента уходит именно в этот туннель, не затрагивая маршрут по умолчанию сервера.

### Файлы и каталоги

| Путь | Содержимое |
|---|---|
| `/opt/l2xpanel` | Код панели и virtualenv |
| `/etc/l2xpanel/panel.env` | Настройки запуска и секреты ([пример](deploy/panel.env.example)) |
| `/etc/l2xpanel/certs` | Выпущенные сертификаты |
| `/var/lib/l2xpanel/store.json` | База: клиенты, inbounds, outbounds, маршруты, настройки |
| `/var/lib/l2xpanel/admin.json` | Учётная запись администратора (bcrypt) |
| `/var/lib/l2xpanel/l2tp*`, `ipsec/` | Профили туннелей и зашифрованные секреты |
| `/etc/xray/config.json` | Конфиг Xray (генерируется панелью, не редактируйте вручную) |

### Порты

| Порт | Назначение |
|---|---|
| 80/tcp | Панель (через nginx) и проверка Let's Encrypt |
| 443/tcp | Все inbounds через nginx (Xray — только 127.0.0.1, порты inbounds закрыты снаружи) |
| 2096/tcp | HTTPS-сервер подписок (если включён) |
| 2053/tcp | Дополнительный HTTPS-listener панели (если включён) |

## Безопасность

- Сразу после установки смените пароль и включите 2FA (**Settings → Security**).
- Задайте секретный путь панели (**Settings → Panel**): страница входа будет доступна только по `http://IP/<путь>/`. Подписки и API продолжат работать по корню.
- API-токены хранятся только в виде хеша; создавайте отдельный токен для каждой интеграции.
- Ограничьте доступ к порту 80 с панелью файрволом, если она нужна только вам, или используйте HTTPS-listener на 2053.
