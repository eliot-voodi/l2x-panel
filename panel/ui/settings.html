Совместимость старых ссылок (3x-ui и др.)

Токен клиента при миграции сохраняется. Если в старой панели путь был не /sub/ (например /zdgdjmy3kho5i6qg/) и/или порт 2096 — укажите их здесь, чтобы старые URL продолжили открываться без смены у пользователей.
HTTP — без TLS (как 3x-ui sub, http://host:2096/…). HTTPS — с сертификатом публичного домена (PasarGuard https://host:8000/sub/…). iptables не блокирует эти порты.
Токены подписки PasarGuard подписаны этим ключом — с ним панель принимает любые ранее выданные ссылки клиентов (поиск по id пользователя PasarGuard). Заполняется автоматически при импорте бэкапа.

Здоровье outbound в подписке

{{ m.check('hide_unhealthy', sb.hide_unhealthy if sb.hide_unhealthy is defined else true, 'Скрывать disconnected / high-loss outbound из подписки') }}
L2TP не в connected, custom с проваленным тестом, или loss выше порога — не попадают в подписку (и в balancer), пока не восстановятся. Клиент увидит изменения после обновления подписки.

JSON-подписка: Fragment / Noise / Mux

Вставляются в outbound proxy конфигов ?format=json. Mux по умолчанию выключен (иначе сильно режет скорость, особенно upload). Включайте явно: {"enabled":true,"concurrency":8,"xudpConcurrency":16,"xudpProxyUDP443":"reject"}. Пустой Fragment/Noise = не трогать.

HWID и смена адреса (Happ)

{{ m.check('hwid_required', sb.hwid_required, 'Обязательный HWID: без заголовка X-HWID подписка не выдаётся') }}
Клиент получает 404 с X-Hwid-Not-Supported, пока не включит отправку HWID. Happ дополнительно получает subscription-always-hwid-enable: 1 и не даст отключить HWID (нужен Provider ID). Устройства видны в карточке клиента.
{% set fb = sb.hwid_fallback or 'device' %}
Работает только у клиентов с лимитом устройств и при выключенном «Обязательном HWID». Версия приложения не учитывается, поэтому обновление не создаёт новое устройство. Режим «по одному приложению» считает два телефона с одним и тем же приложением за одно устройство — дополняйте его лимитом одновременных IP.
{{ m.check('migrate_url', sb.migrate_url, 'Переносить клиентов на текущий адрес подписки при следующем обновлении (new-url)') }}
Если клиент обновляет подписку по старому адресу (другой домен, порт или http), в ответе уходит new-url с актуальной ссылкой: домен/порт/путь из настроек выше. Старый адрес должен продолжать открываться, пока клиенты не обновятся. Работает в Happ при заданном Provider ID.

Прокси для Telegram

Весь трафик бота и уведомлений к api.telegram.org (long-poll, sendMessage, бэкапы) идёт через прокси. MTProto для Bot API не подходит (это протокол клиентов) — используйте HTTP/SOCKS5 или outbound VLESS из панели.
{{ m.check('proxy_enabled', px.enabled, 'Прокси включён') }}
Панель поднимет локальный SOCKS 127.0.0.1:10929 в Xray и направит его в выбранный outbound (VLESS и т.п.).
Команды админа: /status /report /online /clients /tunnels /usage <email> /backup /restart_xray. Клиент может привязать Telegram на странице подписки — в боте /status (срок, оставшиеся ГБ), /unlink. Уведомления пользователю: за N дней до конца срока — раз в день; если осталось < 5 ГБ — один раз (до сброса трафика).

Выпустить сертификат Let's Encrypt

acme.sh через nginx (webroot): проверка идёт без остановки панели. Без nginx — standalone, веб-сервер на :80 останавливается на время проверки. Сертификаты: /etc/l2xpanel/certs, автопродление acme.sh.
Для IP домен не нужен: Let's Encrypt выдаёт сертификат на 6 дней (профиль shortlived), acme.sh продлевает его каждые ~3 дня автоматически. Порт 80 должен быть открыт снаружи.
